## Build

```bash
./gradlew assembleDebug            # debug APK
./gradlew bundleRelease            # signed AAB for Play (SIGNING.md)
./gradlew :app:testDebugUnitTest   # unit tests (JVM)
```

- Use Android Studio's JBR as JDK (`C:/Program Files/Android/Android Studio/jbr`).
- Signing: `gradle/signing.gradle` reads the password from the Windows Credential Manager (`{{CREDENTIAL}}`). Never put passwords in any file. A release build that prints `UNSIGNED` means the credential or the keystore is missing: `setup-signing.ps1 -Register` (SIGNING.md).

## Language rule

## Architecture

FILL: layers and packages (ui / domain / data), navigation, threading.

- Single responsibility: screens (Activity, Fragment, Composable) only wire views and state; feature logic goes in its own class or package. If you are adding feature logic to a screen file, stop and create the right class.
- **No direct database calls outside repositories.** Repositories map storage rows to domain models; the UI never imports `com.erc.dal`.
- Sync fields (`itemStatus`, `syncStatus`, `lastUpdated`) are only set through repository methods (`saveNew`, `saveUpdated`, `markDeleted`), never by hand, and always with the `ItemStatus` / `SyncStatus` enums (no magic numbers).
- Every external dependency (Bluetooth, Drive, network, clock, permissions) sits behind an interface, so tests and Maestro can use a fake.

## Own libraries

Built from source as Gradle modules (`settings.gradle`); read their `README.md` / `CLAUDE.md` before using them:

- DAL, not Room: entities extend `Entity` with `@Table` / `@Field` / `@PrimaryKey` (`@field:` in Kotlin). A new table bumps the DB version and adds an explicit migration in the `UpgradeListener`.
- A feature a library lacks is added **to the library**, backwards compatible (other apps use it): new methods or options with defaults, never a changed signature or behaviour. Note it in the commit and never commit or push in the library repo without asking.
- Logs never contain secrets or personal data (passwords, tokens, e-mails, names, locations, user text). Release logs: level `warn`, no `rest`, no `overlay`.

## Code style

- Self-documenting code: meaningful names, small methods, early returns, at most 2-3 levels of nesting.
- Comments only for public APIs, non-obvious business rules and complex algorithms; no comments that restate the code.
- No magic numbers: named constants. No duplicated logic: extract it.
- All user-visible text in `res/values/strings.xml` (English is the default `values/`), translations in `values-<lang>/`. No hard-coded strings in code or layouts.
- Legal documents (privacy, terms, licenses) are in English only, in `app/src/main/assets/legal/`, and are never translated.

## Bug fix rule (mandatory)

Every bug fix includes a regression test that fails on the old code and passes with the fix. Fix the root cause, not the symptom. Plain JVM JUnit tests: when the logic lives in a screen, adapter or DB model, extract it into a small class with an interface for its dependencies and test that class. Document the crash (exception, frame, scenario) in the test's doc comment. `./gradlew :app:testDebugUnitTest` must pass before finishing.

## Device testing (adb)

- `adb` is not on PATH: `~/AppData/Local/Android/Sdk/platform-tools/adb.exe`.
- In Git Bash, prefix device commands with `export MSYS_NO_PATHCONV=1;` (otherwise `/sdcard/...` becomes `C:/Program Files/Git/...`).
- One signing key for everything (`signing.signDebug=true`): debug, release and Play's app signing key are the same. FILL: a debug build without `applicationIdSuffix` installs over the Play version keeping its data; with a suffix it installs next to it.
- Back up app data and preferences to the scratchpad before changing them on the device, and undo test-only changes afterwards. Never wipe the user's data.
- Find tap targets with `adb shell uiautomator dump`; crashes with `adb logcat -d -b crash`.

## UI tests (Maestro)

Flows in `.maestro/`. Select by `id` (Compose `testTag` exposed as resource-id), every flow starts from a shared launch subflow, never `clearState`, no `:` in `name`, ASCII-only `inputText`. Debug-only deep links (`src/debug/`) open screens and fake scenarios directly.

## Credentials and git

- Tokens, keys and passwords never appear in the chat, the repo or any file: Windows Credential Manager only, typed in a separate window.
- Commit only when the user asks; never push without asking. Never commit `*.jks`, `keystore.properties`, `google-services.json` with secrets, or `.claude/settings.local.json`.
